# Копия прошивки с солнечным дизайном

Это отдельная копия проекта ChickenHouse с переносом солнечного оформления из `design-examples/sunny-prepared.html`. Родительский проект не изменён. Git-история и старые каталоги сборки не копировались; эта папка может быть открыта в VS Code как отдельный проект PlatformIO.

## Что изменено

- В `src/web_pages.cpp` применены тёплая палитра, общая навигация, пиктограммы и цветовые блоки для климата, вентиляции, лаза, кормления и освещения. На главной сохранены реальные поля и обновление данных, добавлены переходы к подробным страницам. На узких экранах навигация прокручивается по горизонтали, а регистры отображаются отдельными блоками.
- Существующие маршруты и методы, обработчики страниц, скрипты обновления, формы, команды и проверки администратора сохранены. Добавлен маршрут `GET /sunny-logo.png`: изображение выдаётся локально из памяти прошивки, интернет для него не нужен. Оптимизированный логотип — `src/sunny_logo.h`, исходное изображение находится в `design-examples`.
- Адреса и поведение Modbus, JSON API, MQTT, настройки, порядок команд и права доступа не менялись. R100 остаётся регистром целых команд.
- Пользовательские подписи без технических номеров регистров; диагностическая страница регистров сохраняет адреса и флаги.

## Проверки и ограничения

26 ноября 2026 года выполнена `pio run -e esp32dev`: сборка успешна, RAM 50 492 из 327 680 байт (15,4 %), flash 1 218 905 из 1 966 080 байт (62,0 %). Компилятор показал предупреждения устаревшего вызова в библиотеке eModbus/AsyncTCP.

Выполнены `node test/sunny_integration_test.js`, `node test/display_formats_test.js`, `node test/alerts_display_test.js`. Контрактный тест сверяет сохранение идентификаторов страниц, исходных маршрутов и девяти скриптов данных с сохранённым снимком `test/sunny_contract_baseline.json`.

Фактическую работу ESP32, подключение к AP и через роутер, авторизацию, OTA, обмен с Modbus Master, MQTT и Telegram на стенде не проверяли. Визуальная проверка на телефоне, планшете и ПК не проводилась: инструмент браузера ранее запретил открытие локального `file:`. До загрузки проверить применимые пункты `docs/pre-flash-checklist.md`, особенно доступ к панели после запуска, при недоступном Master и после перезапуска. Проверка команд, которые двигают оборудование или перезагружают контроллер, — только на безопасном стенде.

Присутствует существующее несоответствие: обработчик `/saveMQTT` принимает `mq_topic`, а существующая форма настроек поле топика не выводит. В этой копии логика MQTT не менялась; это нужно разбирать отдельно до настройки интеграции.

Файл прошивки после сборки: `.pio/build/esp32dev/firmware.bin`. Он не загружался на устройство. Обозначение версии сохранено как `0.0.1-dev`, это не подтверждённый выпуск.

Проверка `node test/settings_manual_scan_test.js` выполняет скрипт страницы и подтверждает отсутствие автоматического запроса и наличие запроса при нажатии. ## Удаление режима администратора

По прямому запросу владельца режим администратора, пароль и сессия веб-панели удалены из этой копии. Без входа доступны страница OTA, приём файла OTA, изменение настроек, смена пароля AP и разрешённые внешние команды через `/api/write_reg`. Любой клиент, имеющий сетевой доступ к ESP32, сможет выполнять эти действия; это относится как к точке доступа, так и к сети роутера. Пароль Wi-Fi/AP сохраняется, как и ограничения карты: R100 — только допустимые целые команды, R101 — разрешённое ненулевое значение, занятость проверяется независимо, запись прочих регистров и отдельных битов через веб/API запрещена. MQTT и Modbus не менялись. При отключении режима ранее сохранённый пароль администратора не читается и не стирается автоматически; существующий заводской сброс по-прежнему очищает и старое хранилище `webAdmin`.

Разделы этого файла выше описывают историю изменений до удаления режима администратора, поэтому упоминания там о его сохранении относятся к прежней версии. Перед использованием проверить доступ к панели и OTA через AP и роутер, допустимые и отклоняемые записи на безопасном стенде. На устройство эта версия пока не загружалась.

## Трактовка R3:B1

По уточнению владельца R3:B1 трактуется инверсно прежнему описанию: при отключённом календаре `0` означает включённый свет днём, `1` — отключённый. На главной странице и странице освещения отображается соответствующее состояние; диагностика регистров показывает сырой бит с пояснением. Само значение Holding-регистра, Modbus, JSON HTTP API и MQTT не изменяются. При включённом управлении по календарю на главной по-прежнему приоритетно выводится режим календаря. Проверка `node test/light_active_low_test.js` покрывает оба состояния бита и приоритет календаря; сборка `pio run -e esp32dev` прошла. Поведение с Master на устройстве не проверялось.

## Актуальность данных контроллера — 60 секунд

По запросу владельца статус `stale` и предупреждение о потере связи/устаревших данных включаются через 60 секунд без изменения R17, включая период после запуска до первого изменения. При подтверждённом изменении R17 данные снова считаются актуальными. Порог R100 для сообщения «Команда не подтверждена» по `0x01FF` остался 10 секунд; период публикации MQTT-статуса также не менялся. Поскольку уведомление о влажности работает только при `fresh`, оно теперь может продолжать использовать последние данные до перехода в `stale` на 60-й секунде. Регистры и формат API не менялись.
