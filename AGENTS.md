# ChickenHouse: контекст проекта

## Назначение

Проект — прошивка модуля ESP32 Dev для системы управления курятником. ESP32 является Modbus Slave-шлюзом: предоставляет ведущему контроллеру карту Holding-регистров и служит для получения и передачи их значений. Она также даёт пользователю веб-интерфейс для контроля и управления, а MQTT и HTTP API позволяют подключать SCADA-системы.

Внешние участники системы: самодельный контроллер Modbus Master (марка и модель не известны), SCADA-системы через MQTT и HTTP API, а также владелец курятника через веб-интерфейс ESP32.

На данный момент клиентов MQTT и Home Assistant нет; возможности интеграции предусмотрены на будущее.

Для MQTT и HTTP API согласован снимок регистров в существующем JSON-формате с адресами в качестве ключей. Статус актуальности данных Master и результаты команд передаются отдельно; приём команды ESP32 и выполнение Master — разные состояния. Точные MQTT-топики, схема ответов, QoS и retain ещё не определены.

Главная страница показывает сводные блоки; отдельные страницы разделов предоставляют более подробную информацию.

## Технологии и сборка

- PlatformIO, окружение `esp32dev`, Arduino framework; параметры и библиотеки — в `platformio.ini`.
- Владелец прошивает устройство через расширение PlatformIO в Visual Studio Code; сейчас используется COM6, но номер порта может измениться. Проект хранится на GitHub.
- После неудачного обновления восстановление выполняется перепрошивкой ESP32 через USB.
- Отдельной версии прошивки, принятой за эталон, сейчас нет. Первой проверенной версии следует присвоить номер `0.0.1`; для каждой версии в GitHub фиксировать краткий список изменений.
- Источники находятся в `src/`; карта регистров — в `src/registers.cpp`.
- Предусмотренная команда сборки: `pio run -e esp32dev`.
- Не добавлять секреты, реальные пароли, токены или Wi-Fi учётные данные в репозиторий.

## Где искать

- `src/main.cpp` — запуск ESP32, Wi-Fi/AP, веб-маршруты, Modbus RTU, MQTT, авторизация и OTA.
- `src/registers.cpp` / `src/registers.h` — карта регистров `memo`.
- `src/web_pages.cpp` / `src/web_pages.h` — страницы и API веб-интерфейса.
- `src/telegram.cpp` / `src/telegram.h` — Telegram и логика уведомления о тревогах.
- `docs/architecture.md` — обзор компонентов и потоков данных.
- `docs/register-map.md` — подтверждённая семантика карты регистров; неизвестные значения остаются помеченными как неизвестные.
- `docs/hardware.md` — подтверждённое подключение оборудования и открытые вопросы.
- `docs/pre-flash-checklist.md` — проверки перед загрузкой прошивки; пункты будущих возможностей помечены отдельно.
- `docs/firmware-gap-report.md` — выявленные расхождения прошивки и требований.

## Рабочие правила

- Перед изменениями просмотреть текущие исходники и соответствующую документацию: документация может отставать от кода.
- Считать фактом только явно подтверждённые спецификации. Помечать выводы как предположения и спрашивать владельца, если ответ влияет на протокол, безопасность или работу оборудования.
- Не менять адреса/значения Modbus, MQTT-топики, поведение регистров, физические параметры линии или последовательность управления без подтверждённой спецификации.
- Регистр 100 используется для команд Master: `0x01` в старшем байте, код команды в младшем. Например, `0x0102` сбрасывает аварию датчика температуры, а `0x0103` — команда с кодом `03`. После выполнения Master записывает `0x0000`. См. `docs/register-map.md`; не менять механизм без согласования.
- Внешняя запись в R101 разрешена, хотя его команды и их формат ещё не определены. Занятость R100 и R101 проверяется независимо.
- Актуальный источник описаний регистров — `docs/register-map.md`. Документ «АКУР прием-передача(NEW3).doc» устарел; не использовать его как источник после уточнений владельца.
- Номера регистров в карте — адреса Modbus с отсчётом от нуля: R0 соответствует адресу 0, R100 — адресу 100.
- Аварийные биты устанавливает и сбрасывает Modbus Master; ESP32 получает их состояние и информирует пользователя. Правила отдельных уведомлений и контроля предела влажности описаны в документации.
- R1:B5 — аварийный режим управления нагревателем; R1:B10 — авария датчика температуры; R0:B14 — фактическое состояние нагревателя. На главной странице показывать состояние нагревателя и общее сообщение с подробностями активных аварий; R1:B5 показывать на странице «Аварии и ошибки».
- Требуемое поведение: при занятом командном регистре отклонять новую команду с уведомлением; если R17 не меняется более 10 секунд, предупреждать об устаревших данных. Сверять реализацию с кодом, не считать эти требования уже реализованными.
- После запуска до первого изменения R17 показывать ожидание данных; более 10 секунд без изменения — предупреждение о потере связи или устаревании данных. Для `0x01FF` ожидать обнуления R100 от Master, не очищать регистр по таймеру; после 10 секунд без подтверждения показать «Команда не подтверждена» и продолжать ожидание.
- Доступ владельца к веб-интерфейсу ESP32 критичен. При изменениях Wi-Fi, AP, DNS captive portal, HTTP-маршрутов, авторизации или сессий нужно сохранять возможность подключиться к панели и проверять этот сценарий.
- Требования к настройкам: имя точки доступа `ChickenHous` сохраняется; пользователь может сменить пароль точки доступа и пароль администратора расширенного режима. Изменение реализовано в исходном коде; проверить доступ на устройстве.
- Заводской сброс удержанием не менее 3 секунд возвращает пользовательские настройки к первоначальному состоянию, сохраняя версию прошивки. Выбран GPIO27 с внутренней подтяжкой и программным подавлением дребезга; перед монтажом проверить доступность вывода и проверить сброс на стенде.
- Telegram предназначен для важных событий. Первым этапом реализован выбор уведомления о влажности: повторы по умолчанию выключены, предлагаемый интервал 30 минут. Прочие существующие уведомления сохраняют прежнее поведение до согласования перечня. Пределы параметров настраиваются на странице «Аварии и ошибки».
- Уведомления Telegram направляются в один чат, Chat ID которого пользователь указывает в настройках.
- Для контроля осушителя требуется настраиваемый верхний предел влажности в курятнике (R6), по умолчанию 95%, и оповещение сразу при его превышении, без дополнительной задержки.
- Изменения прошивки описывать вместе с затронутыми регистрами, API и настройками; сохранять совместимость, если не согласовано иное.
- Не добавлять новые зависимости без необходимости и отражать их в `platformio.ini`.
- Не утверждать, что сборка или тесты прошли, если они фактически не запускались.

## Подтверждённые текущим кодом параметры

- Плата PlatformIO: `esp32dev`; framework: Arduino; платформа: `espressif32`.
- Владелец указал ESP32-WROOM-32 (`XXSR69`), преобразователь RS-485 ↔ TTL и общее питание через USB Type-C платы ESP32 при разработке. Детали питания и маркировки преобразователя уточняются в `docs/hardware.md`.
- В коде Modbus RTU сервер запускается на `Serial2`, 9600 бод, `SERIAL_8N1`, RX GPIO 16, TX GPIO 17, серверный ID 16.
- Объявленные страницы: `/`, `/autoChickenHous`, `/light`, `/alerts`, `/ventilation`, `/feeding`, `/door`, `/climate`, `/table`, `/settings`, `/update`.
- Веб-запись регистров, настройки и OTA защищены режимом администратора; начальная установка пароля предусмотрена через AP.
- Подробности, которые ещё нужно подтвердить, собраны в `docs/open-questions.md`.
